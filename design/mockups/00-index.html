ClashGO · design explorations · 5 layouts

Five layouts for the bot's control room.

All five render the same data at the real window size — 1200×850, from main.go — with the same four sections, the same Start/Stop control and the same ADB status. They are clickable: use the nav in each one. Layouts 01 and 02 are the two reference-driven directions; 03–05 explore other structures.

These thumbnails need this page opened as a file, not served one file at a time. Open design/mockups/00-index.html directly in your browser (double-click it, or open design/mockups/00-index.html), or serve the folder with cd design/mockups && python3 -m http.server 8000. The links below open each layout full size either way.

01 — LEDGER
01 · inspired by vals.ai

The Ledger

Reference-drivenTop nav, no railRanked tableHighest density

An editorial lab report. Hairline rules instead of shadows, a serif headline that states the finding rather than the page name, and every attack as a ranked row with inline yield meters and tabular-numeral variance. The console becomes a footnote.

Wins at: scanning 84 attacks, spotting outliers, feeling credible.
Costs you: the live log is demoted, and a 5-column table is tight at 1200px.

02 — DECK
02 · inspired by the Freebuff app

Command Deck

Reference-drivenIcon railSession tabsCommand bar

The agent-app language transplanted: a 48px rail, a strip of run-session tabs, a run stream of expandable attack cards, and a persistent slash-command bar as the app's spine. Start/stop is a command, not a button in a sidebar.

Wins at: starting and stopping runs; feeling like a modern product.
Costs you: Config gets demoted to a command, and the dark palette must be reconciled with the gold/elixir identity.

03 — COCKPIT
03 · three-pane agentic standard

Cockpit

Nav / run / inspectorAutonomy dialAlways-visible status

Left nav stays labeled (no hover-collapse), the center shows the live run with the emulator state and a latency sparkline, and a 322px inspector carries attack detail ⇄ config. The bottom bar is permanent: stop, ADB, latency, CPU, and the autonomy dial.

Wins at: watching the bot work while tuning it; the most extensible shell.
Costs you: three panes at 1200px leaves ~660px in the center, and it's the least distinctive of the five.

04 — WALL
04 · dark instrument panel

Telemetry Wall

HeatmapSparklinesPermanent logSlide-over config

A dense grid of live instruments: five KPI tiles with sparklines, a capture-latency heatmap across the whole session, a 40-attack gold series, strategy attribution, and a log column that never stops streaming. Config slides over so you can tune without losing the wall.

Wins at: long sessions; absorbs new metrics (SQLite stats, win-rate over time) without a redesign.
Costs you: the highest build cost, and it leans hardest into the dark-on-dark layering the app has fought before.

05 — DISPATCH
05 · one scrolling document

The Dispatch

No tabsTimeline viewProse entriesCollapsed controls

No navigation at all. The bot appends to a single document that reads top to bottom: a summary masthead, then one prose entry per notable attack with the reasoning written out, then a live entry with a blinking caret. Parameters collapse into one line at the top. This is the agentic-UX Timeline View pattern taken literally — the whole four hours is auditable start to finish.

Wins at: catching up after being away; the reasoning is legible to a human, not just a log line.
Costs you: worst for live control, and long sessions create an unbounded scroll that will need virtualization.
