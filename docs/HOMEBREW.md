# Homebrew (macOS) 🍺

ClashGO ships a Homebrew cask so GUI installs and upgrades are managed by
Homebrew instead of the DMG drag-and-drop.

`Casks/clashgo.rb` is generated by `tools/gen_cask.sh` from the release DMG
(version + SHA-256). The copy in this repo tracks the latest published release;
`make brew-cask` regenerates it from a local build.

---

## Install

```bash
brew install --cask dsargent21/tap/clashgo
```

Homebrew 7 requires third-party taps to be trusted before it loads their
casks; if it refuses the tap, run `brew trust dsargent21/tap` once.

To try the checked-in cask before the tap repo exists, seed a throwaway local
tap — Homebrew rejects casks that live outside a tap:

```bash
brew tap-new --no-git dsargent21/tap
TAP_DIR="$(brew --repository)/Library/Taps/dsargent21/homebrew-tap"
mkdir -p "$TAP_DIR/Casks" && cp Casks/clashgo.rb "$TAP_DIR/Casks/"
brew trust dsargent21/tap
brew install --cask dsargent21/tap/clashgo
brew untap dsargent21/tap        # when finished testing
```

Homebrew verifies the DMG against the cask's pinned SHA-256, installs
`ClashGO.app` into `/Applications`, and removes it cleanly on uninstall:

```bash
brew uninstall --cask clashgo
brew uninstall --zap --cask clashgo   # also removes ~/Library/Application Support/ClashGO
```

## Upgrade

```bash
brew update
brew upgrade --cask clashgo
```

`livecheck` reads the `version` field from the release's `latest.json`, so
`brew livecheck --cask clashgo` reports a new release even before the tap is
synced.

## Release automation

`make release` renders `build/bin/clashgo.rb`; the release workflow uploads it
as a release asset and then, **only when `HOMEBREW_TAP_TOKEN` is configured**,
pushes it to the tap:

```
release tag  →  build/bin/clashgo.rb  →  DSargent21/homebrew-tap/Casks/clashgo.rb
```

Add `HOMEBREW_TAP_TOKEN` in **Settings → Secrets and variables → Actions**: a
fine-grained PAT with `contents: write` on the tap repo. Without it, releases
still publish the cask asset and the tap simply stays at its last version.

## Setup (one time)

1. Create the tap repo `DSargent21/homebrew-tap` (empty is fine; a GitHub repo
   cannot be created from CI without broader credentials).
2. Add the `HOMEBREW_TAP_TOKEN` secret described above.
3. Seed the tap with the checked-in cask, either by hand:

   ```bash
   git clone git@github.com:DSargent21/homebrew-tap.git
   mkdir -p homebrew-tap/Casks
   cp Casks/clashgo.rb homebrew-tap/Casks/
   cd homebrew-tap && git add Casks/clashgo.rb && git commit -m "clashgo: add cask" && git push
   ```

   or run the same helper CI uses:

   ```bash
   HOMEBREW_TAP_TOKEN=<pat> tools/sync_homebrew_tap.sh Casks/clashgo.rb DSargent21/homebrew-tap
   ```

4. Verify:

   ```bash
   brew tap dsargent21/tap
   brew info --cask clashgo
   ```

## Notes

- The cask is arm64-only (`depends_on arch: :arm64`), matching the released
  Apple Silicon builds.
- No Apple Developer ID yet, so builds are ad-hoc signed. Homebrew-installed
  copies are not quarantined, which is why the cask install launches without the
  "damaged" dialog that a browser-downloaded DMG can trigger.
- The headless CLI lives in the CLI tarball, not the cask; install it with
  `tools/install.sh --cli` (see the main README).
